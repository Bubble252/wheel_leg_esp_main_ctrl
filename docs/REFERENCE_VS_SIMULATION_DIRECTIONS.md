## 零、什么是左腿、什么是右腿

### 定义

参考代码 `chassisR_task.c` 的文件头注释：

```
从底盘上往下看，右上角的DM4310发送id为6、接收id为3，
右下角的DM4310发送id为8、接收id为4，
右边DM轮毂电机发送id为1、接收id为0。
```

`chassisL_task.c` 的文件头注释：

```
从底盘上往下看，左上角的DM4310发送id为8、接收id为4，
左下角的DM4310发送id为6、接收id为3，
左边DM轮毂电机发送id为1、接收id为0。
```

**"从底盘上往下看"** 是关键视角。这意味着：
- **观察者站在机器人上方**，俯视机器人底盘
- **机器人有一个明确的"前方"**（机器人前进的方向）
- **"右"= 以机器人前进方向为前，位于机器人右侧的腿**（不是观察者的右，也不是面对面的右）

```
                 俯视图（从底盘上往下看）

                      前进方向
                         ↑
                         |
            ┌────────────────────────┐
            │       机  身  (Body)     │
            │                         │
   左腿 ←   │       ● IMU            │   → 右腿
  (CAN2)    │                         │    (CAN1)
            └────────────────────────┘
                         |
                      后方

  左上角 = 前方左侧      右上角 = 前方右侧
  左下角 = 后方左侧      右下角 = 后方右侧
```

| 腿 | CAN总线 | 轮毂电机 | 关节电机 | 在底盘的哪一侧 |
|----|---------|---------|---------|--------------|
| **右腿** | CAN1 | `wheel_motor[0]`, id=1 | `joint_motor[0]`(id=6, 右上=前方), `joint_motor[1]`(id=8, 右下=后方) | 机器人前进方向的右手边 |
| **左腿** | CAN2 | `wheel_motor[1]`, id=1 | `joint_motor[2]`(id=6, 左下=后方), `joint_motor[3]`(id=8, 左上=前方) | 机器人前进方向的左手边 |

> **⚠️ 关键: "左上角/左下角"是俯视图的概念。**
> 右腿: 上角=前方, 下角=后方。左腿: **上角=前方, 下角=后方**（俯视时左右对称）。
> 但注意左腿的 phi1 对应的是 `joint_motor[2]`（左下角=后方），而右腿的 phi1 对应 `joint_motor[0]`（右上角=前方）——这就是五连杆镜像。

## 一、MATLAB 仿真模型的正方向

MATLAB 模型是一个 **2D 侧视图模型**，只建模了一条腿。

### 1.1 观察视角

MATLAB 模型的坐标系：
- `x` 是水平轴
- `y` 隐含为竖直轴（体现在 sin/cos(theta) 等）

从动力学方程看：

```matlab
% 质点水平位置:
% 轮心: x
% 摆杆质心: x + L*sin(theta)
% 机体质心: x + (L+LM)*sin(theta) - l*sin(phi)
```

当 θ=0 时，`L*sin(0)=0`：**摆杆竖直向上**（sin=0，竖直方向用 cos 投影）。
当 θ>0（小正值）时，`L*sin(θ)>0`：**摆杆质心向 x 正方向偏移**。

再看竖直投影：`L*cos(theta)`，θ=0 时 cos=1，质心在正上方。θ增大时 cos 减小。

**结论: MATLAB 是从机器人的右侧看（right side view），θ 逆时针为正（向后摆），x 向左为正。**

等等——让我再仔细推导 x 的方向。

### 1.2 x 的正方向推导

运动方程 eqn1:
```matlab
eqn1: diff(x,t,2) = (T - N*R) / (Iw/R + mw*R)
```

当系统静止（N≈0 的简化情况）：`ẍ ≈ T / (Iw/R + mw*R)`

分母 `Iw/R + mw*R` 总是正的。所以 **T>0 → ẍ>0 → x 增大**。

现在看 eqn2（摆杆方程）简化分析：
```matlab
eqn2: Ip*d²θ/dt² = (P*L+PM*LM)*sin(θ) - (N*L+NM*LM)*cos(θ) - T + Tp
```

重力项 `P*L*sin(θ)`: P 包含 `M*g`（向下的力），L>0, sin(θ)。
当 θ 是小正值时，sin(θ)>0，重力项为正，使 θ 加速增大 → **θ=0 是不稳定平衡**（倒立摆）✅

T 项: `-T`。当 T>0 时使 d²θ 减小。物理含义：轮子向 x 正方向加速时，反作用力使摆杆向 θ 减小的方向转 → **T>0 使 θ 减小 = 腿前摆**。

因此从侧视图看：
- θ 增大 = 腿向一个方向摆
- T>0 使腿向相反方向摆
- T>0 同时使 x 增大

物理直觉：轮子向前加速 → 惯性使腿向后摆 → θ 应该增大。
但方程说 T>0 使 θ 减小？

这说明 **T>0 是轮子向 x 正方向的加速**，而 **x 正方向 = 向后方向**（从右侧看向左）。

不对，让我重新想。MATLAB 模型的 θ 是从竖直向上量起，逆时针为正。如果我从右侧看：
- θ 逆时针 = 腿顶端向左偏 = 腿向"后"摆（假设前方在右侧）

实际上 MATLAB 的 2D 模型并没有定义"前后"。它只是一个数学模型。**"前进"是我们赋予 x 增大方向的含义。** 

让我换一种方式，从控制效果来判断：

LQR 设计好以后，`u = -K*x`，当 pitch 前倾（φ>0）时，T 应该使机器人前进去追回重心。
MATLAB 中 φ>0 = 前倾，T = -K[4]*φ。如果 K[4] <0（需要看实际数值），则 T>0，x 增大 = 前进。

但不同参数下 K[4] 的符号需要实际计算才知道。让我从参考代码端来验证。

### 1.3 从参考代码验证 x 的方向

参考代码的被注释掉的观测器代码：
```c
// chassis_move.v_filter = (wheel_motor[0].para.vel - wheel_motor[1].para.vel) * (-0.0603f) / 2.0f;
// 注释: 0.0603是驱动轮半径，电机正方向定义是逆时针为正，乘半径后得到线速度，
//       数学模型中定义的正方向是逆时针为正，所以需要乘个负号
```

这说明：
- 电机角速度正方向 = 逆时针（从轮轴方向看）
- 线速度 = 角速度 × 半径 = 逆时针方向
- 但 **MATLAB 模型的 x 正方向** 需要乘负号

也就是说：**电机逆时针转的线速度方向 ≠ x 正方向，需要取反**。

从右侧看：
- 轮子逆时针转 → 接地点向右移 → 机器人向左移
- x 正方向 = 机器人向左移？不对...

让我想清楚。假设从右侧看，轮子逆时针转，那么接地点的运动方向是向右的（接地点在底部，逆时针时底部向右），所以机器人整体向左运动。如果 MATLAB 的 x 正方向也需要取反才对应电机的逆时针，那么 x 正方向确实不是逆时针对应的方向。

实际上更活跃使用的观测器代码是：
```c
wr = -chassis_move.wheel_motor[0].para.vel - INS.Gyro[1] + right.d_alpha;
```

右轮的角速度已经被取反了（`-motor[0].vel`）。这是因为：
1. 电机报告的角速度是电机轴的转速，正方向是某个约定方向
2. 取反后得到 MATLAB 模型下的轮子对地角速度

### 1.4 最终结论：MATLAB 仿真的正方向

从 MATLAB `get_k_length.m` 的动力学方程和参考代码的使用方式，综合推断：

| 变量 | MATLAB 正方向 | 物理含义 |
|------|-------------|---------|
| **θ (theta)** | 逆时针为正（从右侧看） | θ=0 腿竖直向上；θ=π 腿竖直向下 |
| **dθ** | 逆时针加速（从右侧看） | 同 θ 方向 |
| **x** | **向左为正**（从右侧看） | 这是"机器人前进"的方向 |
| **v = dx/dt** | 向左为正（从右侧看） | 前进速度 |
| **φ (phi)** | 逆时针为正（从右侧看） = 前倾 | φ>0 鼻子朝下 |
| **dφ** | 逆时针加速（从右侧看） | 同 φ 方向 |
| **T** | T>0 → x 增大（向左/前进） | 驱动轮前进力矩 |
| **Tp** | Tp>0 → θ 增大趋势 | 使腿逆时针（向后摆） |

> **MATLAB 模型等效于"从机器人右侧看"的 2D 侧视图。**
> 
> 这个视角下：
> - 左 = 机器人前进方向
> - 右 = 机器人后退方向
> - 逆时针 = 上→左→下→右
>
> ```
>        从右侧看的侧视图
>  
>     x 正方向 (前进)                   后退
>        ←──────────────────────────→
>                    θ ↺ (逆时针为正)
>                    |
>                    | 腿 (θ=0 时竖直向上)
>                    |
>               ─────●───── 地面
>                   轮子
>  
>     T>0: 轮子接地点向右推地 → 机器人向左(前进) → x增大
>     φ>0: 机体逆时针转 → 前倾
> ```

## 二、参考代码右腿 (chassisR_task.c)

### 2.1 IMU 读数

```c
PitchR = ins->Pitch;          // 直接用，后仰为正
PitchGyroR = ins->Gyro[1];    // 直接用，后仰角速度为正
```

**Pitch 与 MATLAB φ 的关系:**
- MATLAB: φ>0 = 前倾（逆时针，从右侧看）
- 参考代码: Pitch>0 = 后仰
- **φ_matlab = -Pitch_ref**

### 2.2 五连杆运动学

```c
// chassisR_feedback_update():
vmc->phi1 = π/2 + joint_motor[0].para.pos;   // joint_motor[0] = id=6, 右上角 = 前方关节
vmc->phi4 = π/2 + joint_motor[1].para.pos;   // joint_motor[1] = id=8, 右下角 = 后方关节
```

五连杆的 ABCDE 点定义（参考代码中的坐标系）：

```
     从右侧看 (即MATLAB视角):
     
     A(phi1)────l1────B
     |                  \
     l5(机架)            l2
     |                    \
     E(phi4)────l4────D    C (虚拟足端)
                          /
                        l3
```

- **A 点**: phi1 所在的电机，对右腿是 `joint_motor[0]` (右上角=前方)
- **E 点**: phi4 所在的电机，对右腿是 `joint_motor[1]` (右下角=后方)
- **A 在前方, E 在后方**（右腿从右侧看，前方在左边）

> 注意: 这里的"前方/后方"是相对于机器人行进方向的。从右侧看，前方在画面左侧。

phi0 和 L0:
```c
XC = l1*cos(phi1) + l2*cos(phi2);
YC = l1*sin(phi1) + l2*sin(phi2);
L0 = sqrt((XC - l5/2)^2 + YC^2);        // AE 中点到 C 的距离
phi0 = atan2(YC, XC - l5/2);             // AE 中点到 C 的极角
```

平衡时腿竖直向下: phi0 ≈ -π/2 (C 点在 AE 中点正下方, Y<0)

alpha:
```c
alpha = π/2 - phi0;    // 平衡时 alpha = π/2 - (-π/2) = π
```

### 2.3 theta 和 d_theta

```c
// VMC_calc_1_right():
PitchR = ins->Pitch;                    // 后仰为正
PitchGyroR = ins->Gyro[1];              // 后仰角速度为正
theta = π/2 - PitchR - phi0;            // 平衡时 = π/2 - 0 - (-π/2) = π
d_theta = -PitchGyroR - d_phi0;         // 平衡时 = 0
```

**theta 的正方向验证:**

当机体后仰（PitchR 增大）→ theta 减小（因为 `-PitchR`）。
从 MATLAB 角度看: 后仰 = φ<0 = 机体顺时针（从右侧看），这会使 theta... 
在 MATLAB 中 theta 是腿相对于世界坐标的角度。后仰使腿顶端（机架）顺时针转，所以腿相对于世界的角度也顺时针转 → theta 减小。✅ 符号一致。

当 phi0 增大（腿往前摆, C 点往前移）→ theta 减小（因为 `-phi0`）。
从几何看: phi0 增大意味着从 AE 中点到 C 的方向更偏水平向前，即腿往前摆。腿往前摆 = 从右侧看顺时针 = theta 减小。✅ 符号一致。

**平衡值**: theta = π。这对应 MATLAB 的 θ 从竖直向上量起逆时针转了 π → 腿竖直向下。✅

### 2.4 LQR 控制律

```c
wheel_T = K[0]*(theta - 0)
        + K[1]*(d_theta - 0)
        + K[2]*(x_filter - x_set)           // 右腿: x - x_set
        + K[3]*(v_filter - 0.4*v_set)       // 右腿: v - 0.4*v_set
        + K[4]*(PitchR - 0.04 - phi_set)    // 右腿: Pitch - offset
        + K[5]*(PitchGyroR - 0);            // 右腿: PitchGyro

Tp     = K[6]*(theta - 0)                   // 注意: 没有 theta_set
        + K[7]*(d_theta - 0)
        + K[8]*(x_filter - x_set)
        + K[9]*(v_filter - 0.4*v_set)
        + K[10]*(PitchR - 0.04 - phi_set)
        + K[11]*(PitchGyroR - 0);

Tp += leg_tp;                               // 防劈叉
wheel_T -= turn_T;                          // 转向 (右轮减去)
```

**pitch 方向的处理:**

MATLAB 中 K[4] 对应的是 φ (前倾为正), 但右腿直接传入 `PitchR` (后仰为正)。
这意味着 `K[4] * PitchR = K[4] * (-φ_matlab)`。

但是! 我们已经确认多项式拟合的是 +K_matlab, 所以这里有一个 **隐含的符号不匹配**。

然而实际情况是: MATLAB 的 K 矩阵由数值计算得到, K[4] 的符号本身就编码了 `u = -K*x` 中关于 φ 的反馈方向。当我们把 `-φ` (即 Pitch) 传入 `K[4] * Pitch` 时, 多项式拟合出来的 K[4] 的数值大小和其他耦合项一起, 使得整个系统在 theta=π (而非 θ=0) 附近正确工作。

**更直接的理解**: 参考代码是一个**已经调通的系统**, 它的 K×state 产生正确的控制效果。我们的目标不是从头推导为什么符号对, 而是**精确对照参考代码, 确保我们的代码一致**。

### 2.5 输出使用

```c
// 右轮: 直接使用 wheel_T
mit_ctrl2(&hfdcan1, 0x01, ..., chassis_move.wheel_motor[0].wheel_T);  // 右边轮毂电机

// 右腿关节: VMC_calc_2 计算
torque_set[0] = j11*F0 + j12*Tp;   // 给 joint_motor[0] (id=6, 右上角=前方)
torque_set[1] = j21*F0 + j22*Tp;   // 给 joint_motor[1] (id=8, 右下角=后方)
```

**右轮电机扭矩方向:**
从观测器代码看, `wr = -motor[0].vel - INS.Gyro[1] + d_alpha`, 其中 `-motor[0].vel` 表明电机正转（正 vel）对应的轮子转速需要取反才符合 MATLAB 约定。

wheel_T > 0 → 发送正扭矩给电机 → 但由于符号约定, 这是否使轮子在 MATLAB 意义下正转还需要看电机安装方向。

从控制效果来看:
- wheel_T = K[0]*theta, 平衡时 theta=π
- 如果 theta 略大于 π（腿向后摆多了）, K[0]<0（查表）, 则 K[0]*theta < K[0]*π, 增量为负 → wheel_T 变小 → 减速/后退 → 追回腿
- ✅ 这是正确的物理响应

### 2.6 右腿各变量正方向总结

| 变量 | 参考代码右腿的正方向 | 与 MATLAB 的关系 |
|------|-------------------|----------------|
| **theta** | 逆时针（从右侧看）= 向后摆 | θ_ref = θ_matlab + π, 方向相同 |
| **d_theta** | 逆时针加速 = 向后摆加速 | 完全对应 |
| **x_filter / v_filter** | 前进为正 | = MATLAB 的 x 增大方向 |
| **PitchR** | 后仰为正 | = -φ_matlab |
| **PitchGyroR** | 后仰角速度为正 | = -dφ_matlab |
| **wheel_T > 0** | 发给电机的正扭矩 | 使 x 增大（前进）? 需看电机映射 |
| **Tp > 0** | 由 LQR 算出, 使 theta 有增大趋势 | = Tp_matlab 方向 |

## 三、参考代码左腿 (chassisL_task.c)

### 3.1 核心差异: IMU Pitch 取反

```c
// chassisL_feedback_update():
chassis->myPitchL = 0.0f - ins->Pitch;         // Pitch 取反!
chassis->myPitchGyroL = 0.0f - ins->Gyro[1];   // PitchGyro 取反!
```

**为什么取反?**

MATLAB 模型是从右侧看的 2D 模型。当我们要复用这个模型来控制左腿时, 需要建立一个**左腿的等效视角**。

从**左侧看**机器人：
- 左侧和右侧是镜像的
- 从右侧看: 后仰 = 顺时针; 从左侧看: 后仰 = **逆时针**
- 所以同样的 IMU 读数 (后仰为正), 从左侧看时 angular direction 是反的
- 为了让 LQR（基于右侧视角推导）正确作用于左腿, 需要把 Pitch 取反

简单说: **Pitch 取反是为了把 IMU 读数从"右侧视角"转换到"左侧视角"。**

### 3.2 五连杆运动学（镜像）

```c
// chassisL_feedback_update():
vmc->phi1 = π/2 + joint_motor[2].para.pos;   // joint_motor[2] = id=6, 左下角 = 后方关节
vmc->phi4 = π/2 + joint_motor[3].para.pos;   // joint_motor[3] = id=8, 左上角 = 前方关节
```

**对比右腿:**

| 属性 | 右腿 | 左腿 | 说明 |
|------|------|------|------|
| phi1 对应 | joint_motor[0], 右上角=**前方** | joint_motor[2], 左下角=**后方** | **镜像!** |
| phi4 对应 | joint_motor[1], 右下角=**后方** | joint_motor[3], 左上角=**前方** | **镜像!** |

这意味着：
- 右腿: A 点 (phi1) 在前方, E 点 (phi4) 在后方
- 左腿: A 点 (phi1) 在**后方**, E 点 (phi4) 在**前方**

```
     从左侧看 (左腿的 MATLAB 等效视角):
     
                B────l1────A(phi1)    ← 左腿的 A 点在后方
               /                |
             l2               l5(机架)
            /                   |
          C    D────l4────E(phi4)    ← 左腿的 E 点在前方
            \
             l3
     
     注意: A 和 E 的位置与右腿镜像!
     前进方向 →→→ (从左侧看, 前进方向向右)
```

但由于 phi1 和 phi4 的电机调换了, **五连杆运动学的数学公式完全不变** — XB,YB,XC,YC 的计算方式和右腿相同, 只是输入的关节角度来自不同的物理电机。

**这使得从"左侧看"时, 五连杆的几何行为和从"右侧看右腿"完全对称。** phi0, L0, alpha 的计算公式不需要修改。

### 3.3 theta 和 d_theta

```c
// VMC_calc_1_left():
PitchL = 0 - ins->Pitch;                // 取反!
PitchGyroL = 0 - ins->Gyro[1];          // 取反!

theta = π/2 - PitchL - phi0;            // = π/2 - (-Pitch) - phi0 = π/2 + Pitch - phi0
d_theta = -PitchGyroL - d_phi0;         // = -(-PitchGyro) - d_phi0 = PitchGyro - d_phi0
```

**左腿 theta 的平衡值:**
平衡时 Pitch=0, phi0≈-π/2:
```
theta_L = π/2 + 0 - (-π/2) = π   ✅ 与右腿相同
```

**左腿 theta 的动态:**
- Pitch 增大（后仰）→ theta 增大（因为 `+Pitch`）
- 而右腿: Pitch 增大 → theta 减小（因为 `-Pitch`）

这个差异是正确的! 因为:
- 从右侧看: 后仰 → 腿顶端顺时针(向后) → theta 减小
- 从左侧看: 后仰 → 腿顶端逆时针(向后, 从左侧看方向反了) → theta 增大

### 3.4 LQR 控制律

```c
wheel_T = K[0]*(theta - 0)
        + K[1]*(d_theta - 0)
        + K[2]*(x_set - x_filter)           // ← 翻转! (目标 - 实际)
        + K[3]*(0.4*v_set - v_filter)        // ← 翻转! (目标 - 实际)
        + K[4]*(PitchL - (-0.04))            // PitchL = -Pitch, 偏移也取反
        + K[5]*(PitchGyroL - 0);

Tp     = K[6]*(theta - 0 + theta_set)        // 注意: 有 theta_set (防劈叉)
        + K[7]*(d_theta - 0)
        + K[8]*(x_set - x_filter)            // ← 翻转!
        + K[9]*(0.4*v_set - v_filter)        // ← 翻转!
        + K[10]*(PitchL - (-0.04))
        + K[11]*(PitchGyroL - 0);

Tp += leg_tp;
wheel_T -= turn_T;                           // 左轮也是减去 turn_T!
```

### 3.5 左腿 x/v 翻转的原因

右腿 LQR: `K[2]*(x - x_set)`，前进过多 → 正值 → T 做出修正。
左腿 LQR: `K[2]*(x_set - x)`，**取反了**。

**为什么?**

这和轮子电机的物理方向有关。参考代码中左右轮毂电机是**镜像安装**的:
- 右轮: 正扭矩 → 从右侧看逆时针 → 接地点向右 → 机器人向左 = **前进**
- 左轮: 正扭矩 → 从左侧看逆时针 → 接地点向左 → 机器人向右 = **后退**

所以左轮的正扭矩使机器人后退! 为了让同一组 K 增益对左轮也产生"前进过多 → 减速"的效果, 需要翻转 x/v 的误差符号。

**验证:** 
观测器中 `aver_v = (vrb - vlb) / 2.0f;`（右减左取平均）。如果两轮同向（前进）, 右轮体速度 vrb 为正, 左轮体速度 vlb 为负（因为左轮电机正向导致的线速度方向相反）, 相减后为两倍正值, 取平均后 v>0 = 前进。✅

### 3.6 左腿 Pitch 的处理

展开左腿 pitch 项:
```c
K[4]*(PitchL - (-0.04))
= K[4]*(-Pitch - (-0.04))
= K[4]*(-Pitch + 0.04)
```

**对比右腿:**
```c
K[4]*(PitchR - 0.04)
= K[4]*(Pitch - 0.04)
```

两者: 左腿 = `K[4]*(-Pitch + 0.04)`, 右腿 = `K[4]*(Pitch - 0.04)`。**符号相反。** ✅

这和上面 Pitch 取反的道理一致: 从左侧看, 后仰变成了"等效前倾", 所以 pitch 项需要取反。

### 3.7 左腿轮毂电机输出

```c
// 注意: 左轮也是 -= turn_T, 不是 +=
wheel_T -= turn_T;

// 发送:
mit_ctrl2(&hfdcan2, 0x01, ..., chassis_move.wheel_motor[1].wheel_T);
```

**左右轮都减去 turn_T** — 因为电机镜像安装, 同号操作在物理上产生差速效果。

### 3.8 左腿各变量正方向总结

| 变量 | 参考代码左腿的正方向 | 与右腿的关系 | 与 MATLAB 的关系 |
|------|-------------------|-------------|----------------|
| **theta** | 逆时针（从**左**侧看）= 向后摆 | 平衡值相同=π, 动态方向镜像 | θ_ref_L = θ_matlab + π |
| **d_theta** | 逆时针加速（从左侧看） | PitchGyro 符号相反 | 完全对应 |
| **x_filter / v_filter** | 前进为正 (全局量, 左右共用) | **相同** | = x_matlab 增大方向 |
| **PitchL** | **前倾为正** (= -IMU.Pitch) | = -PitchR | = +φ_matlab |
| **PitchGyroL** | 前倾角速度为正 | = -PitchGyroR | = +dφ_matlab |
| **x_err** | `x_set - x` (与右腿反号) | **翻转** | 补偿左轮电机方向 |
| **v_err** | `v_set - v` (与右腿反号) | **翻转** | 补偿左轮电机方向 |
| **wheel_T > 0** | 发给左轮电机的正扭矩 | 物理上使机器人**后退** | 因此 x/v 翻转补偿 |
| **Tp > 0** | 使 theta 有增大趋势 | 方向相同 (从各自视角看) | = Tp_matlab 方向 |

- 可能的解释: K[4] 在 theta=π 处的数值计算中, 与 theta 的偏移量 π 产生的常数项抵消后, 剩余的动态项恰好能正确处理 Pitch 方向

## 五、观测器 (observe_task.c)

### 5.1 右轮体速度

```c
wr = -chassis_move.wheel_motor[0].para.vel - INS.Gyro[1] + right.d_alpha;
vrb = wr * 0.0603 + right.L0*right.d_theta*cos(right.theta) + right.d_L0*sin(right.theta);
```

分解:
- `-motor[0].vel`: 电机角速度取反 (电机正转方向 ≠ MATLAB 正方向)
- `-INS.Gyro[1]`: 减去 pitch 角速度 (机体转动对轮子接地角速度的影响)
- `+right.d_alpha`: 加上腿部摆动对轮子接地角速度的影响
- `wr * R`: 接地点线速度
- 后面两项: 腿部长度/角度变化引起的末端运动补偿, 把接地点速度转换到"体坐标系"速度

### 5.2 左轮体速度

```c
wl = -chassis_move.wheel_motor[1].para.vel + INS.Gyro[1] + left.d_alpha;
vlb = wl * 0.0603 + left.L0*left.d_theta*cos(left.theta) + left.d_L0*sin(left.theta);
```

**与右轮的差异:**
- `+INS.Gyro[1]` (右轮是 `-INS.Gyro[1]`): Pitch 角速度的影响方向对左轮取反

### 5.3 平均速度

```c
aver_v = (vrb - vlb) / 2.0;
```

**注意是 vrb - vlb, 不是 (vrb + vlb)/2!**

原因: 左轮电机镜像安装, vlb 的符号约定和 vrb 相反。当两轮同向前进时:
- vrb > 0 (右轮正常前进)
- vlb < 0 (左轮"正"速度 = 后退, 前进时 vlb<0)
- vrb - vlb = vrb + |vlb| > 0
- 除以 2 = 平均前进速度 ✅

### 5.4 卡尔曼滤波

```c
xvEstimateKF_Update(&vaEstimateKF, -INS.MotionAccel_b[0], aver_v);
```

- 状态: [速度, 加速度]
- 观测 1: aver_v (前进速度)
- 观测 2: `-INS.MotionAccel_b[0]` (体坐标系 x 方向加速度取反)

加速度取反说明 IMU 的体坐标系 x 轴正方向与 MATLAB 的前进方向相反。

## 六、关键结论与陷阱

### 6.1 MATLAB 是从右侧看的

所有 K 增益都是基于**从右侧看**的 2D 模型推导的。左腿通过:
1. Pitch 取反
2. phi1/phi4 电机互换（五连杆镜像）
3. x/v 误差翻转

来复用**同一组 K**。

### 6.2 "左""右"的严格定义

> **"右" = 以机器人前进方向为前方，位于机器人右手侧的腿。**
> **"左" = 以机器人前进方向为前方，位于机器人左手侧的腿。**
> 
> 不是面对面看，不是从某个特定角度看。就是**机器人自身的左右**。

### 6.3 仿真到嵌入式的三处符号差异

| 差异 | MATLAB 仿真 | 参考代码 | 如何处理 |
|------|------------|---------|---------|
| **θ 平衡值** | 0 | π | K×state 中 θ≈π 的数值自然处理 |
| **φ vs Pitch** | 前倾为正 | 后仰为正 | 右腿直接传入; 左腿取反后传入 |
| **左轮电机方向** | 仅一个轮 | 镜像安装 | 左腿 x/v 翻转, 两轮同号减 turn_T |

### 6.4 五连杆镜像的本质

并不是把五连杆的几何"翻转"了, 而是把 **phi1/phi4 对应的物理电机互换**了。
数学上五连杆运动学公式不变, 但输入的关节角来自不同位置的电机, 使得从**左侧看**时的五连杆行为和从**右侧看右腿**的行为完全一致。

> 逐项验证其物理含义是否自洽。

### 7.0 Q/R 权重矩阵回顾

### 7.3 逐场景物理直觉验证 (@ L0=0.14m, MATLAB 坐标系)

> MATLAB 中 `u = -K*x`，下面每个场景只有一个状态非零，计算 T 和 Tp 的响应。

**⚠️ 读前必看: 理解 Tp 的两个关键直觉**

很多场景下 Tp 的方向看起来 "反物理直觉"。在读具体场景前，先建立两个核心心智模型:

**直觉 1: Tp 的本质是 "迈步"，不是 "推倒"**

Tp 控制的是腿的摆动方向。腿摆动 = 足端（支撑点）移动。
- Tp<0 → 腿前摆 → 足端往前挪 → 类似 **往前迈一步**
- Tp>0 → 腿后摆 → 足端往后挪 → 类似 **往后退一步**

当你快摔倒时，你不会傻站着，你会 **朝摔倒的方向迈一步接住自己**。
LQR 的 Tp 做的就是这件事: **哪边倾了就往哪边 "迈步"，把支撑点挪到重心正下方。**

**直觉 2: T 在倒立摆中是 "反的"**

普通小车: 超前了就刹车。倒立摆: **超前了反而要先加速前进!**

为什么? 因为倒立摆不能直接刹车（刹车会摔倒）。要后退，必须:
1. 先短暂前推 → 惯性使机体后仰
2. 后仰后，重力自然驱动后退
3. φ 反馈 (K[4]) 接管，完成位置修正

所以 T 对 x/v 的响应方向和普通小车是 **反的**。这不是 bug，是倒立摆控制的本质特征。

#### 场景 1: θ=+0.05 rad — 腿向后多摆了 2.9°

```
T  = -K[0]*0.05 = -(-1.45)*0.05 = +0.072 Nm (前进)
Tp = -K[6]*0.05 = -(+2.64)*0.05 = -0.132 Nm (腿前摆)
```

**物理直觉**:
- 腿向后偏了 → 轮子向前加速追回腿下方 → T>0 ✅
- 腿向后偏了 → 髋关节推腿往前摆回正 → Tp<0 ✅
- |Tp| > |T|：主要靠髋关节直接回正，轮子辅助 ✅ 合理

---

#### 场景 2: d_theta=+0.5 rad/s — 腿正在向后摆

```
T  = -K[1]*0.5 = -(-0.17)*0.5 = +0.086 Nm (前进)
Tp = -K[7]*0.5 = -(+0.36)*0.5 = -0.179 Nm (腿前摆)
```

**物理直觉**:
- 腿在向后摆 → 用 T 和 Tp 阻尼这个运动 → 方向同场景 1 ✅
- 这是速度阻尼项，幅度比位置项稍大（因为 0.5 rad/s 比 0.05 rad 数值大 10 倍）

#### 场景 3: x=+0.1 m — 机器人比目标位置多前进了 10cm

```
T  = -K[2]*0.1 = -(-0.64)*0.1 = +0.064 Nm (继续前进!)
Tp = -K[8]*0.1 = -(+1.37)*0.1 = -0.137 Nm (腿前摆)
```

**物理直觉 — ⚠️ T>0 看似违反直觉，实则是倒立摆特有行为!**

普通小车：超位置了 → 刹车/后退。简单。

但倒立摆不能直接刹车，否则会摔倒!倒立摆的位置修正策略是：

1. x 偏大（超了目标位置）→ 需要后退
2. 要后退，必须先让机体**后仰** → 这样重力会自然驱动后退
3. 要让机体后仰，必须先**短暂向前加速**（轮子前推，惯性使机体后倾）
4. 机体后仰后，φ 反馈 (K[4]) 接管，产生后退力矩

所以 **T>0 是"先前推以制造后仰"的第一步**。

同时 **Tp=-0.137** 也在帮忙：腿前摆使足端前移，间接调整支撑点。

> ✅ **这是经典的倒立摆"反直觉"位置控制**: 要后退先前进，通过制造倾斜来间接改变位移。
> T=0.064 的幅度 << φ 反馈的 T=-0.168（见场景 5），说明 φ 修正会很快接管。

---

#### 场景 4: v=+0.3 m/s — 机器人以 0.3m/s 向前运动

```
T  = -K[3]*0.3 = -(-0.64)*0.3 = +0.191 Nm (继续前进!)
Tp = -K[9]*0.3 = -(+1.36)*0.3 = -0.408 Nm (腿前摆)
```

**物理直觉**: 与场景 3 完全一致的倒立摆逻辑。

速度过快 → 要减速 → 先加速使机体后仰 → 后仰后自然减速。  
T=+0.191 比 x 修正大 3 倍，因为速度偏差需要更强的响应。

> ✅ 合理。v 的 Q 权重 (5) 是 x 权重 (10) 的一半，但 0.3m/s 的偏差比 0.1m 的偏差"更紧急"。

#### 场景 5: φ=+0.1 rad — 机体前倾 5.7°

```
T  = -K[4]*0.1 = -(+1.68)*0.1 = -0.168 Nm (后退!)
Tp = -K[10]*0.1 = -(+15.62)*0.1 = -1.562 Nm (腿强力前摆!)
```

**物理直觉分析**:

**T = -0.168 (后退)**: 机体前倾时，轮子减速/后退，利用惯性把机体推回正。
这是 "推回正" 策略，而非 "追重心" 策略（追重心应该是 T>0 前进去接住）。
但看幅度，|T|=0.168 只占总控制的一小部分——**LQR 把 φ 修正的重任交给 Tp**。

**Tp = -1.562 (腿前摆)**: 这才是主角!

理解 Tp 的物理含义需要一个关键直觉：
**Tp 改变的是"支撑点相对于重心的位置"，而非机器人整体运动方向。**

```
        前倾时 (φ>0):

        前进 ←           → 后退

        ← 重心偏前了
         CoG
          ↓
          ┌─────────┐ Body (前倾)
         /          │
        /           └───┬──┘
                        │
                   Tp<0 │ ← 腿前摆 = 足端往前挪
                        │
                        ●→ 足端往前移, 靠近重心正下方
                   ═══════════ 地面
```

**腿前摆 = 足端往前移 = 把支撑点挪到重心正下方 = 稳定!**

类比人的动作: **身体前倾快摔倒时，你会往前迈一步接住自己。**
Tp<0 (腿前摆) 就是这个 "往前迈一步"。

> ✅ Tp 主导前倾修正，T 辅助。|Tp/T| ≈ 9.3 倍，符合 R(T)/R(Tp) = 20 的成本比。

#### 场景 6: φ=-0.1 rad — 机体后仰 5.7°

```
T  = -K[4]*(-0.1) = +(+1.68)*0.1 = +0.168 Nm (前进!)
Tp = -K[10]*(-0.1) = +(+15.62)*0.1 = +1.562 Nm (腿后摆!)
```

**物理直觉**: 场景 5 的镜像，理解方式完全一致。

**T>0 (前进)**: 后仰时加速前进，惯性使机体往前倾回正。

**Tp>0 (腿后摆)**: 这看似反直觉——后仰了还让腿往后摆？但关键同样是 **"迈步接住"**:

```
        后仰时 (φ<0):

        前进 ←           → 后退

                         重心偏后了 →
                                     ↓ CoG
              ┌──────────────┐ Body (后仰)
              │              \
              └──┬───────────┘
                 │
            Tp>0 │ ← 腿后摆 = 足端往后挪
                 │
           足端 ←● 往后移, 靠近重心正下方
              ═══════════ 地面
```

**腿后摆 = 足端后移 = 把支撑点挪到重心正下方 = 稳定!**

类比人: **身体后仰快摔倒时，你会往后退一步接住自己。**
Tp>0 (腿后摆) 就是 "往后退一步"。

> ✅ 完全对称。前倾迈前步 (Tp<0)，后仰退后步 (Tp>0)，都是把脚放到重心下面。

#### 场景 7: dφ=+0.5 rad/s — 机体正在向前倾

```
Tp = -K[11]*0.5 = -(+0.71)*0.5 = -0.354 Nm (腿前摆)
```

**物理直觉**:
- 机体正在前倾 → T 和 Tp 都试图阻止前倾继续 ✅
- 这是速度阻尼项，幅度比位置项稍大（因为 0.5 rad/s 比 0.05 rad 数值大 10 倍）

> 方向正确，幅度合理。

#### 场景 8: 综合 — 前倾+超前 (φ=0.08, dφ=0.2, x=0.05, v=0.1)

```
T  = -K[4]*0.08 - K[5]*0.2 - K[2]*0.05 - K[3]*0.1
   = -(1.68*0.08) - (0.09*0.2) + (0.64*0.05) + (0.64*0.1)
   ≈ -0.134 - 0.017 + 0.032 + 0.064
   = -0.056 Nm (微弱后退)

Tp = -(15.62*0.08) - (0.71*0.2) + (1.37*0.05) + (1.36*0.1)
   ≈ -1.250 - 0.142 - 0.069 - 0.136
   = -1.595 Nm (强力腿前摆)
```

**物理直觉**:
- T 几乎为零：φ 的后退力和 x/v 的前进力互相抵消 → 轮子几乎不动
- Tp 很大：所有状态都要求腿前摆 → 大力前摆修正
- **这体现了 LQR 的最优策略**: 用便宜的 Tp 猛修，用昂贵的 T 尽量少动

> ✅ 综合场景下各分量协调一致，无符号矛盾。

### 7.5 K 值随腿长的变化趋势

| 趋势 | 具体数值变化 (L0: 0.10→0.20) | 物理解释 |
|------|---------------------------|---------|
| **|K[0,1]| 随 L0 增大而增大** | θ→T: -1.15 → -1.80 (+56%) | L0 大 → 腿长 → 摆杆力矩臂大 → θ 偏差更危险 → 需要更强的 T 修正 |
| **|K[4,5]| 随 L0 增大而减小** | φ→T: +2.21 → +1.21 (-45%) | L0 大 → 系统重心更高 → 倒立摆效应更强 → φ 的"自修正"能力更强 → T 需求反而减小 |
| **|K[6]| 随 L0 增大而减小** | θ→Tp: +2.97 → +2.32 (-22%) | L0 大 → Tp 力矩臂大 → 同样扭矩产生更大效果 → 不需要那么大的增益 |
| **K[7] 几乎不变** | dθ→Tp: 0.36 → 0.36 (-2%) | dθ 的阻尼需求与 L0 几乎无关 |
| **|K[8,9]| 随 L0 增大而减小** | x→Tp: +1.80 → +0.99 (-45%) | L0 大 → Tp 力臂大 → 较小增益即可 |
| **K[10,11] 随 L0 增大而增大** | φ→Tp: +14.2 → +16.6 (+17%) | L0 大 → 重心更高 → φ 更不稳定 → 需要更大 Tp 来补偿 ⚠️ 与 K[4] 趋势相反! |

**K[10] 和 K[4] 的趋势为什么相反?**

这是一个有趣的观察:
- K[4] (φ→T) 随腿长增大而**减小**: 腿越长，T 对 φ 的响应越弱
- K[10] (φ→Tp) 随腿长增大而**增大**: 腿越长，Tp 对 φ 的响应越强

物理解释: 腿越长时，Tp 的力矩臂增大，直接控制 φ 的效率更高，
所以 LQR 选择**更多依赖 Tp 而非 T** 来修正 φ。
这也符合 R(Tp)=1 << R(T)=20 的成本结构: 随着 Tp 效率提升，LQR 自然倾向用更多 Tp。

### 8.0 参考代码中变量的物理含义（从代码直接读取）

以下所有定义均来自 `chassisR_task.c`、`VMC_calc.c`、`observe_task.c`，不引用任何 MATLAB。

#### 8.0.1 theta 和 d_theta（来自 VMC_calc_1_right）

```c
// VMC_calc.c  VMC_calc_1_right()
PitchR = ins->Pitch;
vmc->phi0 = atan2f(vmc->YC, (vmc->XC - vmc->l5/2.0f));
vmc->theta = pi/2.0f - PitchR - vmc->phi0;
vmc->d_theta = (-PitchGyroR - vmc->d_phi0);
```

- `phi0`: 虚拟腿（从髋关节中点到轮轴的连线）**相对于水平面**的夹角。站立时 phi0 ≈ π/2（腿竖直向下）。
- `theta = π/2 - Pitch - phi0`: 这是**虚拟腿相对于重力方向的偏角**。
  - 站立平衡时: Pitch≈0, phi0≈π/2 → **theta ≈ 0**（不是 π！参考代码中 theta 在平衡点附近就是 0）
  - 如果机体前倾 (Pitch 变负，因为 IMU 前倾 Pitch 为负) → theta 增大
  - 如果虚拟腿前摆 (phi0 < π/2) → theta 增大

> ⚠️ **关键发现**: 参考代码中 `theta` 平衡值是 **≈0** 而非 ≈π。
> 公式 `theta = π/2 - Pitch - phi0` 在 Pitch≈0, phi0≈π/2 时 → theta≈0。
> 这与 LQR 状态量 `theta - 0.0f` 完全一致！

#### 8.0.2 x 和 v（来自 observe_task.c）

```c
// observe_task.c
wr = -chassis_move.wheel_motor[0].para.vel - INS.Gyro[1] + right.d_alpha;
vrb = wr*0.0603f + right.L0*right.d_theta*arm_cos_f32(right.theta)
    + right.d_L0*arm_sin_f32(right.theta);

wl = -chassis_move.wheel_motor[1].para.vel + INS.Gyro[1] + left.d_alpha;
vlb = wl*0.0603f + left.L0*left.d_theta*arm_cos_f32(left.theta)
    + left.d_L0*arm_sin_f32(left.theta);

aver_v = (vrb - vlb) / 2.0f;  // 取平均（注意符号是减）
// 经卡尔曼滤波 →
chassis_move.v_filter = vel_acc[0];
chassis_move.x_filter += chassis_move.v_filter * dt;
```

- `x_filter`: 机器人位移，通过轮速积分 + 卡尔曼滤波得到。
- `v_filter`: 机器人速度。
- **正方向**: 右腿 `wr` 的负号 vs 左腿 `wl` 的负号不同 → 左右轮编码器方向相反（面对面安装）。`aver_v = (vrb - vlb)/2` 通过取差来统一方向。

> 关键: 无论正方向如何定义，右腿的 `x_filter - x_set` 和左腿的 `x_set - x_filter` 是**反号**的 → 两腿对 x 偏差的响应方向相反，这是左右对称结构的必然。

#### 8.0.3 Pitch 和 PitchGyro（来自 feedback_update）

```c
// 右腿: chassisR_task.c
chassis->myPithR = ins->Pitch;           // 直接使用
chassis->myPithGyroR = ins->Gyro[1];     // 直接使用

// 左腿: chassisL_task.c
chassis->myPithL = 0.0f - ins->Pitch;    // 取反!
chassis->myPithGyroL = 0.0f - ins->Gyro[1]; // 取反!
```

- IMU 的 Pitch: **后仰为正、前倾为负**（标准 IMU 惯例：抬头 = 正 Pitch）
- 右腿直接用 `ins->Pitch`
- 左腿对 Pitch 取反 → 两腿"前方"定义相反，通过取反统一到同一套 K 值

#### 8.0.4 LQR 公式（右腿，chassisR_task.c line ~190）

```c
wheel_T = K[0]*(theta-0) + K[1]*(d_theta-0)
        + K[2]*(x_filter-x_set) + K[3]*(v_filter-0.4*v_set)
        + K[4]*(PitchR-0.04) + K[5]*PitchGyroR;

Tp = K[6]*(theta-0) + K[7]*(d_theta-0)
   + K[8]*(x_filter-x_set) + K[9]*(v_filter-0.4*v_set)
   + K[10]*(PitchR-0.04) + K[11]*PitchGyroR;
```

这就是全部：**T = +K × 误差**，K 由多项式拟合，误差 = 各状态量 − 目标值。

### 8.1 L0=0.14m 时的 K 值（参考代码 Poly_Coefficient 直接计算）

使用 `chassisR_task.c` 中硬编码的 `Poly_Coefficient[12][4]` 和 `LQR_K_calc()`:

```
K[ 0] = -4.85   (theta → wheel_T)      K[ 6] = +2.30   (theta → Tp)
K[ 1] = -0.43   (d_theta → wheel_T)    K[ 7] = +0.23   (d_theta → Tp)
K[ 2] = -1.47   (x_err → wheel_T)      K[ 8] = +1.15   (x_err → Tp)
K[ 3] = -1.42   (v_err → wheel_T)      K[ 9] = +1.04   (v_err → Tp)
K[ 4] = +2.19   (Pitch_err → wheel_T)  K[10] = +9.57   (Pitch_err → Tp)

```

符号规律: **K[0..3] 全部为负，K[4..11] 全部为正。**

### 8.2 逐场景物理直觉验证（右腿视角，纯从代码出发）

> **约定**: 每个场景仅讨论**一个状态量偏离平衡点**时的 K 项贡献，其余假设在平衡值。

---

#### 场景 1: theta > 0（虚拟腿偏离竖直）

**物理情况**: `theta = π/2 - Pitch - phi0`。theta > 0 意味着虚拟腿相对于重力方向偏了——可能是腿前摆了或机体后仰了（但此处单独讨论 theta，Pitch 项另算）。

**代码响应**:
- `wheel_T += K[0] * theta = (-4.85) × (+) = 负` → 轮子反向力矩
- `Tp += K[6] * theta = (+2.30) × (+) = 正` → 髋关节正向力矩

**物理直觉**:
1. 虚拟腿偏了 → 轮子需要反向移动，把底盘"拉回"到腿正下方 → wheel_T 反向 ✅
2. 同时髋关节产生力矩把腿摆正 → Tp 正向 ✅

**幅度比较**: |K[0]| = 4.85 >> |K[6]| = 2.30
- 轮子（T）是维持平衡的主力，如同骑独轮车时脚蹬是第一反应
- Tp 是辅助——不能仅靠摆腿来平衡 ✅

---

#### 场景 2: d_theta > 0（虚拟腿正在偏离的速度）

**代码响应**:
- `wheel_T += K[1] * d_theta = (-0.43) × (+) = 负`
- `Tp += K[7] * d_theta = (+0.23) × (+) = 正`

**物理直觉**: 方向与场景 1 一致——这是**阻尼项**，抑制 theta 的变化速率。

幅度约为场景 1 的 1/10，与 Q 矩阵中 dθ 权重(0.07)远小于 θ 权重(1) 一致。✅

---

#### 场景 3: x_filter > x_set（机器人跑过了目标位置）

**代码响应**:
- `wheel_T += K[2] * (x_filter - x_set) = (-1.47) × (+) = 负` → 轮子反向
- `Tp += K[8] * (x_filter - x_set) = (+1.15) × (+) = 正` → 髋关节正向

**物理直觉**:
1. 跑过头了 → 轮子反向拉回 → wheel_T 负 ✅
2. 髋关节力矩使虚拟腿倾斜，通过改变倒立摆平衡点来辅助减速 → Tp 正 ✅

> 类比: 人跑过头了要向后仰身体来刹车。Tp 正 = 虚拟腿正向摆动 = 创造一个"后仰"趋势来减速。

---

#### 场景 4: v_filter > 0.4*v_set（机器人速度太快）

**代码响应**:
- `wheel_T += K[3] * (...) = (-1.42) × (+) = 负`
- `Tp += K[9] * (...) = (+1.04) × (+) = 正`

**物理直觉**: 与场景 3 完全类似。K[2]≈K[3], K[8]≈K[9] → LQR 对位移和速度的响应权重接近。✅

> 注: 速度目标是 `0.4 * v_set` 而非 `v_set`——经验参数，可能为了更平滑的加速。

---

#### 场景 5: PitchR > 0.04（机体后仰超过平衡偏置） ⭐ 最关键场景

**物理情况**: IMU Pitch > 0 = **后仰**。PitchR - 0.04 > 0 意味着后仰超过了 0.04 rad（约 2.3°）的预设偏置。

**代码响应**:
- `wheel_T += K[4] * (PitchR - 0.04) = (+2.19) × (+) = 正` → **轮子正向力矩**
- `Tp += K[10] * (PitchR - 0.04) = (+9.57) × (+) = 正` → **髋关节大力矩**

**wheel_T 正向（轮子向前移动）的物理直觉**:

```
        后仰状态:
        
          重心 ← 落在轮轴后方
           \
            \  机体
             \
              ●─ 轮轴
             ╱
            ╱ 虚拟腿
           ●
           ▼ 轮子需要向后(?)→ 不对!
           
        正确理解:
        - 后仰 → 重心在轮轴后方 → 要防摔倒
        - 轮子正向转 → 反作用力让机体上部向后仰的方向"多仰一点点"？
        
        不! 回忆倒立摆控制的核心:
        - 轮子正向转 → 底盘向前移 → 相当于把"地面支撑点"移到更前面
        - 但重心在后面啊?
        
        再想: 轮子正向转 → 产生向前的地面摩擦力 → 
        作用在机体底部 → 机体底部被推向前 →
        机体上部由于惯性相对后仰 → 这不是更仰了吗?
        
        关键: 这里 wheel_T 的"正方向"到底是什么?
```

> ⚠️ **这里需要非常谨慎**: `wheel_T` 的正方向定义取决于电机驱动方向和 observe_task.c 中的速度符号约定。让我们**不从 wheel_T 的绝对方向去判断**，而是从**与其他项的一致性**来验证。

**换一个验证角度——与 theta 项的一致性**:

考虑后仰对 theta 的影响: `theta = π/2 - Pitch - phi0`
- Pitch 增大（后仰）→ theta 减小 → theta < 0
- K[0] × (theta<0) = (-4.85) × (-) = **正** → wheel_T 正

两条路径得到同一结论:
1. 直接: K[4] × (Pitch-0.04) = (+2.19) × (+) = 正
2. 间接: 后仰 → theta减小 → K[0] × (负theta) = 正

**两条独立路径都给出 wheel_T 正！自洽！** ✅

**Tp 正向（大力矩）的物理直觉**:

- K[10] = +9.57，是 12 个增益中**最大的**
- 后仰时 Tp 正 → 虚拟腿向某个方向摆动
- 对应的物理动作：**调整支撑点位置以防摔倒**
- 类比: 人后仰时脚会向后迈步——**"迈步接住重心"** ✅

**K[10] 为什么是最大增益?**
- Q(Pitch)=300: 机体姿态是最优先保护的状态量
- R(Tp)=1: 髋关节力矩是最"廉价"的控制手段
- 高优先级 + 低成本 = 极大增益 ✅

---

#### 场景 6: PitchR < 0（机体前倾）

**代码响应**:
- `wheel_T += K[4] * (PitchR - 0.04) = (+2.19) × (负) = 负`
- `Tp += K[10] * (PitchR - 0.04) = (+9.57) × (负) = 负`

**与 theta 的一致性验证**:
- 前倾 → Pitch 减小 → theta 增大 → K[0] × (正theta) = (-4.85) × (+) = **负** → wheel_T 负
- 直接路径: K[4] × (负) = 负 ✅ 两条路径一致！

场景 5 和 6 完全对称。✅

---

#### 场景 7: PitchGyroR > 0（机体正在向后仰方向旋转）

**代码响应**:
- `wheel_T += K[5] × (+) = (+0.24) × (+) = 小正值`
- `Tp += K[11] × (+) = (+0.54) × (+) = 小正值`

**物理直觉**: 方向与场景 5（后仰）一致——正在后仰中，需要同样方向但更温和的力矩。这是**角速度阻尼项**。

K[5]/K[4] ≈ 0.11, K[11]/K[10] ≈ 0.06 → 阻尼项约为位置项的 1/10~1/20。✅

### 8.5 "反直觉" 行为的深入解释（纯代码视角）

#### Q1: K[4] > 0 — 后仰时轮子正向转，不是应该反向吗?

> **这是倒立摆控制的核心**: 不是"推回去"，而是"追过去"。
> 
> 验证方法: 看 K[4] 和 K[0] 是否自洽。
> 后仰 → Pitch↑ → theta = π/2 - Pitch↑ - phi0 → theta↓
> - K[4] 路径: K[4]×(Pitch↑) = (+2.19)×(+) = wheel_T 正
> - K[0] 路径: K[0]×(theta↓) = (-4.85)×(-) = wheel_T 正
> 
> **两条完全独立的路径给出同样的结论: wheel_T 正。** 这不是巧合，是自洽。✅

#### Q2: K[0] < 0 — theta 正了轮子反转?

> theta > 0 → 虚拟腿偏离竖直 → 如果是因为轮子跑快了导致腿被"甩"出去 → 轮子应该减速/反向。
>
> 反向理解: 轮子正向加速 → 机体上部惯性后仰 → theta 减小。
> 所以 theta 和 wheel_T 天然负相关 → K[0] < 0。✅

#### Q3: K[10] = +9.57，为什么是最大值?

> - Pitch（机体水平姿态）直接决定机器人是否摔倒 → **最高优先级**
> - Tp（髋关节力矩）是控制 Pitch 最直接的手段 → **最低成本**
> - Q(φ)=300, R(Tp)=1 → 300/1 = 300 的优先级/成本比
> - 对比 K[4]: Q(φ)=300, R(T)=20 → 300/20 = 15
> - K[10]/K[4] ≈ 9.57/2.19 ≈ 4.4，大致反映了 Tp 比 T "便宜" 20 倍的事实 ✅

### 8.6 交叉验证: theta 和 Pitch 对 wheel_T 的贡献方向必须一致

这是一个强有力的一致性检验——因为在参考代码中，theta 和 Pitch 之间有 **确定的数学关系**:

```
theta = π/2 - Pitch - phi0
```

所以当 Pitch 单独增大 ΔP 时:
```
Δtheta = -ΔP
```

wheel_T 的变化:
```
Δ(wheel_T) = K[0] × Δtheta + K[4] × ΔP
            = K[0] × (-ΔP) + K[4] × ΔP
            = (-K[0] + K[4]) × ΔP
            = (4.85 + 2.19) × ΔP
            = 7.04 × ΔP
```

> K[0] 和 K[4] 不但方向一致，而且**叠加增强**! 
> 后仰 (ΔP > 0) → wheel_T 增大 7.04×ΔP。
> K[0] 贡献 4.85, K[4] 贡献 2.19 → 两者协同工作。

同理验证 Tp:
```
Δ(Tp) = K[6] × Δtheta + K[10] × ΔP
       = K[6] × (-ΔP) + K[10] × ΔP
       = (-K[6] + K[10]) × ΔP
       = (-2.30 + 9.57) × ΔP
       = 7.27 × ΔP
```

> K[6] 和 K[10] 也协同工作! K[10] 贡献 9.57, K[6] "削弱" 2.30（因为 theta 减小时 K[6] 项方向相反），净效果 7.27。

**这说明什么?** 当机体后仰时:
1. Pitch 增大 → K[4] 让 wheel_T 正向（直接路径）
2. theta 减小 → K[0] 也让 wheel_T 正向（间接路径）
3. 两者**不矛盾、不抵消，而是合力**

如果某个 K 符号反了，这里就会出现 K[0] 和 K[4] 互相抵消的情况 → 控制效率极低。事实上它们协同，说明**符号完全正确**。✅
